# OCR bruto — Anexo A do WISC-IV (tabelas de conversão por faixa etária)

Texto bruto extraído via OCR (Tesseract 5.4, `--psm 4`) das páginas do Anexo A do "Wisc IV - Manual de Aplicação-compactado.pdf", como passo intermediário para gerar o JSON de seed das `TabelaNormativa`.

**Por que existe esta pasta**: as tabelas do Anexo A são grades numéricas densas (15 colunas × 19 linhas cada, 33 tabelas de conversão ponto-bruto→ponderado por subteste + 11 tabelas de escores de processo). Uma sessão anterior (ver `docs/testes/WASI-tabelas-brutas.json`, campo `_AVISO_ESCALA`) documentou que transcrever esse volume de dados manualmente, célula a célula, direto no chat, tem alto risco de erro por fadiga — a recomendação registrada lá foi usar OCR + revisão, não retranscrição manual. Segui essa recomendação aqui: instalei Tesseract OCR (`winget install UB-Mannheim.TesseractOCR`), renderizei cada página do PDF em 300dpi, rotacionei 90° (o conteúdo das tabelas vem impresso lateralmente no PDF original) e rodei OCR com `--psm 4`.

**Conteúdo**: 44 arquivos `.txt`, um por página/tabela — `a1-*.txt` = Tabelas A.1.1 a A.1.33 (conversão bruto→ponderado, 33 faixas etárias de 4 meses, 6:0 a 16:11); `a8-*.txt` = Tabelas A.8.1 a A.8.11 (escores de processo CUSB/DIOD/DIOI/CAA/CAE, 11 faixas etárias anuais, 3 faixas por página). O nome do arquivo é o número da página do PDF (`wisc_iv_manual.pdf`, versão compactada) de onde veio; cada arquivo se auto-identifica no texto (linha "Tabela A.1.X" / "Idades X:X-X:X").

**Qualidade**: variável. A maioria das tabelas A.1.x saiu bem legível; algumas (ex. a1-263, a1-268) têm linhas com colunas coladas ou dígitos ambíguos. As tabelas A.8.x saíram com qualidade **pior** — o layout empacota 3 sub-tabelas (3 faixas etárias × 5 colunas cada) lado a lado na mesma página, e o OCR embaralhou números entre colunas em vários pontos (visível em a8-283, a8-284 principalmente).

**Status**: isto é matéria-prima, **não dado verificado**. Nenhuma célula foi conferida individualmente contra a imagem original nesta sessão (só o formato geral de 2 tabelas — A.1.1 e A.1.33 — foi conferido visualmente antes de decidir usar OCR). **Não usar estes números direto em produção** (seed do Prisma, cálculo de laudo, etc.) sem antes estruturar em JSON e revisar célula a célula contra o PDF — idealmente com a psicóloga responsável conferindo uma amostra.

**Próximo passo sugerido**: converter estes .txt em JSON estruturado (mesmo formato de `WASI-tabelas-brutas.json`: chave = ponto ponderado 1-19, valor = intervalo de escore bruto, por subteste e faixa etária), tabela por tabela, cruzando com a imagem original nos casos ambíguos — não um parse automático cego do texto OCR.
